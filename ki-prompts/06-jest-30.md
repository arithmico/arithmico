# Migration prompt: Jest 29 → 30

## Context to give the assistant

You are working across two workspaces of the `arithmico` monorepo that both run Jest: `packages/services/api` (`jest` `29.7.0`, using `ts-jest` `^29.4.12`) and `packages/libraries/engine` (`jest` `^29.6.1`, using `@swc/jest` `^0.2.39`). The engine test suite has 20 test suites and 752 tests and must keep passing with the same count; the api test suite currently has 1 test. Test file content must not be changed as part of this migration — only Jest configuration and, if unavoidable, `expect`/matcher setup files.

## Task

Upgrade `jest` from 29 to 30 in both workspaces, along with `ts-jest` and `@swc/jest` to versions that declare support for Jest 30.

1. Read the official Jest 30 release notes and migration guide. Focus on: changes to the default test environment (Jest 30 changes defaults around `testEnvironment` and drops some legacy environments), changes to snapshot format (Jest 30 changes serialization in ways that can invalidate existing `.snap` files), changes to how `moduleNameMapper` and `transform` are resolved, and any change to minimum Node.js version.
2. For the `engine` workspace, verify `@swc/jest` `^0.2.39` (or a newer release) declares compatibility with Jest 30, and check `packages/libraries/engine`'s `jest.config` (or `jest` key in `package.json`) for any option renamed or removed in Jest 30.
3. For the `api` workspace, verify `ts-jest` declares compatibility with Jest 30 and check its `jest` configuration in `package.json` for the same kind of renamed/removed options.
4. If the upgrade changes the snapshot serialization format, regenerate snapshot files with the standard Jest snapshot update mechanism rather than hand-editing them, and treat any resulting `.snap` diff as a review item, not as "test content" that is off-limits — only the test assertions themselves (`.test.ts`/`.spec.ts` files) must stay untouched, not generated snapshot artifacts.
5. Do not change any assertion, test description, or test data in `.test.ts` / `.spec.ts` files.

## Validation checklist

- `npm run test -w engine` reports the same 20 suites and 752 tests, all green.
- `npm run test -w api` reports the same 1 suite and 1 test, green.
- `nx run-many -t test` succeeds for all projects.
- No `.test.ts` or `.spec.ts` file has a content diff beyond formatting; only `jest.config`/`package.json` `jest` blocks and, if applicable, regenerated snapshot files changed.
