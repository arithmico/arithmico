# Migration prompt: Nx 18 → 23

## Context to give the assistant

You are working in the `arithmico` npm workspace monorepo (workspaces: `engine`, `parser`, `ui-components`, `calculator`, `documentation`, `blog`, `backoffice`, `api`). Task orchestration currently runs on Nx 18 via `nx run-many -t test` and `nx run-many -t lint`, configured in the root `nx.json` with `"neverConnectToCloud": true`. This is step 1 of a larger migration plan; no other major dependency has been upgraded yet.

## Task

Upgrade Nx from 18 to the latest 23.x release across the whole workspace.

1. Read the official Nx migration guides for the 19, 20, 21, 22 and 23 major releases and identify every breaking change that applies to an npm-workspaces-based repo (not the default Nx-managed package manager setups), in particular:
   - Changes to `nx.json` schema (task pipeline configuration, `namedInputs`, `targetDefaults`).
   - Changes to how `neverConnectToCloud` / Nx Cloud opt-out is expressed, since telemetry and cloud-connect behavior has changed across majors.
   - Changes to the plugin inference system (`@nx/js`, `@nx/eslint`, `@nx/jest` or equivalent), since newer Nx versions favor plugin-inferred targets over explicit `project.json` targets.
   - Any change to the minimum required Node.js version.
2. Prefer running `nx migrate latest` and reviewing the generated migrations one major version at a time (18 → 19 → 20 → 21 → 22 → 23) rather than jumping directly, so each migration script can apply its automated codemods. Do not skip the intermediate `nx migrate` steps even though only the end state matters for `package.json`.
3. Apply the generated migrations, review every file the migration script touched, and reconcile `nx.json` and any `project.json` files with the new schema.
4. Do not change the `neverConnectToCloud: true` setting or otherwise enable Nx Cloud.
5. Do not modify test files. If a migration codemod touches a test file only for formatting, that is acceptable; do not change test assertions or logic.

## Validation checklist

- `nx run-many -t test` succeeds for all 8 projects with the same test counts as before the migration.
- `nx run-many -t lint` succeeds for all 8 projects.
- `nx run-many -t build` (or the equivalent per-workspace build commands documented in `README.md`) succeeds for `engine`, `calculator`, `documentation`, `blog`, `backoffice` and `api`.
- `nx.json` still has `"neverConnectToCloud": true` and no telemetry or cloud project ID was created.
- Diff `nx.json` and any `project.json` files and confirm every change is explained by a migration note.
